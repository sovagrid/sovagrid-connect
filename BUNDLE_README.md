# SovaGrid Connect — автономная сборка

В архиве находятся два варианта запуска:

- `SovaGrid-Connect-CLI/` — запуск из терминала. Он поддерживает SSH-пароль или ключ и выводит диагностику подключения.
- `SovaGrid-Connect-GUI/` — графический запуск с SSH-паролем, ключом или `ssh-agent`. Существующий приватный ключ выбирается через «Выбрать…», а новая пара Ed25519 создаётся через «Создать…» отдельно для сервера или перехода. Место сохранения выбирается в окне; парольная фраза вводится в скрытых запросах OpenSSH. Готовый приватный путь выбирается автоматически, открытый ключ можно скопировать. Сервер при этом не меняется. На macOS также есть `SovaGrid-Connect-GUI.app`.

Исполняемые файлы находятся внутри папок с тем же именем. Сохраняйте папку GUI целиком: внутренний `SovaGrid-Connect-Askpass` и каталоги `_internal` нужны для графических запросов SSH. macOS `.app` содержит помощник внутри и может запускаться отдельно. Python устанавливать не требуется. Системный OpenSSH (`ssh`, а для создания ключей — `ssh-keygen`) должен находиться в `PATH`. Веб-панель открывается в системном браузере через локальный туннель. После подключения в GUI можно нажать «Получить начальный пароль по SSH» и скопировать его для первого входа в Hub под логином `admin`; SSH-пользователь должен иметь право чтения файла (обычно `root`). После смены пароля Hub в «Настройках» этот начальный пароль уже не подходит. Пароль в GUI не сохраняется и очищается при отключении.

Авторство и лицензии доступны без сети: в GUI откройте «О программе» → «Сторонние лицензии», в CLI выполните `SovaGrid-Connect-CLI third-party-licenses --list` или `SovaGrid-Connect-CLI third-party-licenses ИМЯ_ФАЙЛА`. Тексты также лежат в `legal/third-party/` внутри архива. Linux-сборка добавляет copyright точных системных библиотек, которые вошли в исполняемые файлы; Windows-сборка содержит сведения о Microsoft C runtime. Для автономной Windows-сборки требуется Windows 10 или новее.

Для **первой установки на чистый Ubuntu-сервер** в GUI есть кнопка «Установить на сервер…». Нужны root SSH-вход и отдельный доверенный пакет `SovaGrid-server-source.tar.gz` из пяти серверных репозиториев организации SovaGrid. Выберите его в окне, отметьте функции и дождитесь результата; терминальные команды вводить не требуется. Если SovaGrid уже стоит на сервере, действие безопасно откажет. Пакет не включён в этот архив Connect; проверка хешей и структуры выявляет повреждение, но не заменяет доверие к источнику кода, который будет запущен от root.

Если пакет лежит рядом с папкой GUI или `.app`, диалог первой установки предложит его автоматически и покажет SHA-256. На уже установленном SovaGrid с исходниками в `/opt/sovagrid-src` кнопка «Включить функции…» проверит здоровье и права установки, покажет действующие функции и после отдельного подтверждения включит выбранные через существующий `run.sh`. Это перезапускает Hub/Web и Agent. Обновление исходников и управление Amnezia через эту кнопку не выполняются.

Если на Ubuntu уже работает Agent другого Hub, используйте отдельную кнопку **«Свой Hub на сервере с Agent…»**. Нужен SSH-вход root либо пользователь с уже действующим sudo без запроса пароля и проверенный серверный пакет v0.6.0-preview. Мастер покажет маршрут и SHA-256, прочитает состояние без изменений и попросит подтверждение. Он создаёт отдельный Hub и второго Agent, сохраняя прежний Agent и его туннель. После установки он отдельно проверит здоровье Hub и свежую метрику локального Agent перед открытием панели. При неизвестном или частично установленном состоянии мастер остановится. Публичный HTTPS для такого Hub настраивается отдельно.

Для обновления собственного локального Hub выберите **«Обновить собственный локальный Hub…»**. Сначала мастер только проверит исходники, внешний Agent, пакет и текущую версию, затем после подтверждения сохранит проверенный кандидат. **«Применить обновление»** запускает отдельную операцию с проверкой результата и отката. После первого ручного перехода с 0.3.9 можно разрешить серверу одно обновление при простое из уже подготовленного пакета; «Состояние» показывает политику, а «Снять разрешение» удаляет её. Снятие разрешения не обязано выключать системный timer, но без политики он не применит пакет.

Для отдельного локального Agent есть **«Терминал и файлы своего Hub…»**. Кнопка сначала проверит сервер без изменений и отдельно попросит подтверждение для каждой функции. Если у этого Agent команды пока выключены, откройте отдельное окно **«Разрешить команды своего Hub…»**, проверьте сервер и подтвердите включение. Оно не происходит при выборе терминала или файлов. При параллельном изменении настроек мастера требуют повторной проверки. Выключение команд пока не поддерживается, так как для него нужен отдельный проверенный серверный контракт.

Кнопка «Обновить сервер…» предназначена для уже исправной управляемой установки. Она проверяет пакет и текущие версии, показывает полный SHA-256 и commit ID пяти компонентов, после подтверждения сохраняет проверенный кандидат в `/opt/sovagrid-candidates/<sha256>`. До нажатия «Применить обновление» действующие исходники и службы не изменяются. При применении Connect повторно проверяет пакет и установленную версию, делает закрытую резервную копию исходников, управляемых конфигураций и данных Hub, сохраняет старые образы и после запуска проверяет здоровье служб. При ошибке он пытается восстановить прежнее состояние и показывает результат. Обновление не откатывает APT-пакеты, системных пользователей и возможные внешние побочные действия; при неполном откате резервная копия сохраняется. Пакет должен поступать из доверенного источника: SHA-256 подтверждает целостность, но не происхождение.

Пример CLI: `SovaGrid-Connect-CLI connect --host server.example.com --user root`. Для GUI откройте `SovaGrid-Connect-GUI` или `.app`, укажите SSH-адрес и пользователя и нажмите «Подключиться». При первом подключении сверьте отпечаток SSH-ключа с консолью провайдера или администратором сервера. Пароль SSH, фраза ключа и коды 2FA запрашиваются отдельным окном и не сохраняются.

Сборки создаются отдельно на Windows, macOS и Ubuntu в GitHub Actions. Они не подписаны и не нотариально удостоверены. На другой версии Linux могут отличаться системные библиотеки. CI проверяет запуск собранных программ, офлайн-лицензии и служебный канал Askpass; отдельный Xvfb тест проверяет основные графические окна на Linux. Браузер и соединение с вашим сервером в CI не проверяются. Исходный код и подробная инструкция: [README.md](https://github.com/sovagrid/sovagrid-connect#readme).
